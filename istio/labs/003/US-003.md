# 🚀 Épico C — Ingress Gateway & Gateway CRD

## 📋 US-003 — Publicar serviços via Istio Gateway (Ingress)

### 👤 História do Usuário

**Como** operador  
**Quero** expor o frontend via Gateway e VirtualService  
**Para que** HTTP externo alcance meu serviço através do Istio Ingress Gateway

### ✅ Critérios de Aceitação

- Host configurado no Gateway responde externamente
- VirtualService roteia para frontend corretamente

### 📝 Tarefas

- [ ] 1. Criar e aplicar o Gateway:

```yaml
apiVersion: networking.istio.io/v1beta1
kind: Gateway
metadata:
  name: my-gateway
spec:
  selector:
    istio: ingressgateway
  servers:
    - port:
        number: 80
        name: http
        protocol: HTTP
      hosts: ["*"]
```

- [ ] 2. Criar e aplicar o VirtualService:

```yaml
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: frontend-vs
spec:
  hosts: ["*"]
  gateways: ["my-gateway"]
  http:
    - match:
        - uri:
            prefix: "/"
      route:
        - destination:
            host: "frontend"
            port:
              number: 5678
```

- [ ] 3. Aplicar e verificar acesso:

```bash
# Obter informações do Ingress Gateway
kubectl get svc istio-ingressgateway -n istio-system

# Para ambiente local (minikube/kind), usar port-forward:
kubectl port-forward svc/istio-ingressgateway -n istio-system 8080:80

# Testar o acesso
curl http://localhost:8080/
```

### 🔍 Validação

Para confirmar que a configuração está correta:

```bash
# Verificar resposta do frontend
curl http://localhost:8080/

# Verificar configuração do VirtualService
kubectl get virtualservice frontend-vs -o yaml
```

#### Pontos de Verificação

- [ ] curl retorna resposta esperada do frontend
- [ ] VirtualService está configurado e as rotas estão corretas
